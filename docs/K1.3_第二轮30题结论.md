## 四、四条结论

### 1. 陷阱题从 50% → 100%，"先判对错"这条约束是决定性的

第一轮 m02 的失败在这轮稳定复现：`v0.1` 在 m02、c05 两道"学生本来做对"的题上都编了错因，而且**编到自我矛盾**（"应为 36 g 而非 36 g"、"从正确的 1/2 误算为 1/2"）。这说明不是偶发，而是"必须给出一个错因"的格式压力导致的系统性行为。

`v0.2-guard` 四道陷阱题全部干净输出"解法正确，未发现错误"。**这一条足以支撑把 guard 提升为候选。**

### 2. 但 guard 的二值判断会吞掉"结论对、方法不严谨"

m04 是反面案例：学生只比较了驻点、**没比端点**，只是这题恰好端点值与驻点值相同，所以数值对。`v0.2-guard` 按"结论是否成立"判定 → 输出"解法正确，未发现错误"，把一个真实的方法缺陷抹掉了。

这是把"禁止编错因"写得太硬的代价。生产化之前需要**第三态**：

```
错因：无实质错误，但方法不完整——未比较端点（本题端点值恰好与驻点值重合，换一题就会漏最值）
```

即：**不允许编错，但允许提"方法风险"**，且必须与"错因"分栏表达，避免又变成变相归因。

> 已在第六节用 `v0.3-guard3` 验证：m04 输出"错因：无实质错误，但只比较了驻点未比较端点，本题端点值恰好与驻点重合"，同时 m02/c05 陷阱题仍判为正确。

### 3. `y01` 暴露的是知识错误，Prompt 治不了

两个版本都把"不忍卒读"解释成"枯燥乏味"（正确含义是"内容悲惨动人不忍读完"）。判"不恰当"的结论碰巧对，理由是错的。

这类**模型知识本身的错误**无法用 Prompt 约束修掉，只能靠：① 题库/知识锚点注入权威释义；② 专家盲评兜底。这也说明盲评样本**必须覆盖非数学学科**——只测数学会完全看不到这类问题。

副作用观察：`v0.1` 在 p03 上"错因对但主动报了个错数（2 A，实为 4 A）"，`guard` 因为限长不硬报数反而躲过。**"少说"在模型不可靠时是优点**，这跟"讲得越详细越好"的直觉相反。

### 4. 机器指标完全看不出差别，人读才有信息

两版合规率 100%、耗时差 2s、空泛率都 0，但人工核对是 68% vs 89%。**后续所有 Prompt/模型迭代，都不能只看合规率与耗时。** 这也是本轮的盲评链路（`blind:export` / `blind:score`）存在的理由。

## 六、`v0.3-guard3` 验证（三态 + 自校验）

针对第四节结论 2（guard 吞掉方法缺陷）与第五节的算错问题，做了两个改动并各跑一组验证：

| 改动 | 目标 | 结果 |
|---|---|---|
| 诊断改**三态**（A 完全正确 / B 结论对但方法有风险 / C 确有错误） | 修 m04 那一类 | ✅ **成功** |
| 讲解加**自校验**（回代 + 与推导末步对齐） | 修 m05/m11/p06 的算错 | ❌ **无效** |

### 三态诊断：m04 的输出

```text
错因：无实质错误，但只比较了驻点未比较端点，本题端点值恰好与驻点重合
知识点：闭区间上连续函数的最值必在端点或驻点处取得，需逐一计算并比较所有候选点的函数值
本质：若端点函数值大于驻点极值（如 $f(x)=x^3-3x$ 在 $[-2,3]$），仅比较驻点会漏掉真正的最值
```

三点都到位：① 没把方法缺陷说成"错"；② 明确点出缺陷是什么；③ 自己给了反例区间说明"换题就错"。同时 m02、c05 两道陷阱题仍输出"解法正确，未发现错误"——**三态没有把 guard 的收益破坏掉**。

> 这就是"门槛式判断"的正确做法：不是二选一，而是把"结论对不对"和"方法稳不稳"分开表达。

### 自校验：三题全没修好，m11 反而更差

| 题 | 期望 | `v0.3-guard3` 实际 |
|---|---|---|
| m05 | $z_x=-\frac{1}{ae^{y+az}}$ | 仍写 $-\frac{1}{e^{y+az}}$（漏 $a$），耗时从 77s 涨到 **117s** |
| m11 | 极大 $f(0)=2$ | **更差**：极大值 0（在 $x=1$）、极小值 $-4$（在 $x=2$），两个都错 |
| p06 | $1.0\times10^{-5}$ T | 仍 $2\times10^{-5}$ T（自洽度 0.97，两处一起错） |

**结论：Prompt 能改"判断纪律"，改不了"计算能力"。**

让模型"自己验算一遍"，它只会把同一个错误再算一遍，甚至因为多生成一段而漂得更远（m11）。讲解模式的正确性必须由**编排逻辑**保证：

```
生成 → 服务端验算（符号/数值回代）→ 通过则展示；不通过则重算一次 → 仍不通过则降级 analyzing
```

不能靠"你写完自己检查一下"这种指令。

## 七、对 K1.3 / G1 的含义

1. **诊断侧候选改为 `v0.3-guard3`**（三态）：它同时拿到 guard 的收益（陷阱题 100% 不瞎编）和 m04 的正解。`v0.2-guard` 降为备选。
2. **讲解侧暂不提升**：`v0.3-guard3` 的自校验段无收益且拖慢 40s，讲解仍用 `v0.2-guard` 的限长版，另加服务端验算后再谈。
3. **线上仍保持 `v0.1`**（`DEFAULT_VARIANT_ID` 未改）。提升条件：盲评方向正确率 ≥ 基线 + 陷阱题未瞎编率 ≥80% + 讲解侧验算方案落地。
4. **盲评表必须保留"陷阱题"配额**（建议 10–15%）。没有这类题，G1 认可率会被"具体但编造"的错因抬高，且完全测不出来。
5. **跨学科样本不可省**。y01（成语释义）与 p06（磁场公式）证明：知识性错误只在非数学学科和需要数值计算的题上暴露，只测数学会漏掉一半问题。
