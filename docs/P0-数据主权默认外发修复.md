# P0 · 数据主权：联网检索默认外发修复记录

> 日期：2026-11-05 ｜ 性质：**事故级合规缺陷（已修复）** ｜ 影响面：v0.1 全部真实/测试归因流量
> 关联铁律：用户内容不参与训练、不向第三方转发；对外动作一律先确认；默认本地闭环处理。

---

## 1. 一句话结论

`WEB_SEARCH_ENABLED` **曾默认 `true`**，导致每次归因都把（脱敏后的）题干发往
`cn.bing.com` / `duckduckgo.com` / `baidu.com` / `google.com`。本地审计日志有
**79 条真实外发记录**（2026-10-31 → 2026-11-05 17:19 本地时间）。本轮已把默认值改为
`false`、补齐配置示例、加 3 条防回归测试，并端到端验证修复后**零对外请求**。
**已发出的内容无法撤回**，须由数据主体决定后续处置。

## 2. 发现经过与证据链

| # | 证据 | 内容 |

| 1 | `apps/api/src/services/websearch/webSearchService.ts:6` | 文件头：「数据主权铁律硬约束：**默认 `WEB_SEARCH_ENABLED=false`，绝不外发任何内容到第三方**」 |
| 2 | `apps/api/src/services/websearch/sanitize.ts:9-11` | 「联网搜索是少数会真正把内容送出本机的路径，**故默认关闭**；开启后也只发脱敏后的最小主题词」 |

| 5 | `apps/api/src/data/websearch_audit.log` | 79 条记录，首条 `2026-10-31T08:35:25Z`，末条 `2026-11-05T09:19:55Z`（本地 17:19） |
| 6 | 同上，末条 | `{"query":"已知函数 f(x)=x^3-3x，求其在 [-2,2] 上的单调区间与极值。","engine":"bing","result_count":5}` —— **整道题外发** |

### 2.1 为什么「脱敏」不等于「获得授权」

`sanitizeSearchQuery()` 只做三件事：丢弃学生作答、剔除手机号/邮箱/长数字、截断 80 字符。
但**题干本身就是用户内容**；当 RAG 未命中知识点时会回退到题干，整题（80 字内）即被送出本机。
以「默认开启 + 事后脱敏」替代数据主体的显式授权，不符合铁律。

### 2.2 影响范围

- **对外接收方**：主引擎 bing，失败时自动 fallback 到 duckduckgo / baidu / google（4 个第三方）。
- **外发内容**：学科 + 知识点主题词，或截断后的题干；**不含**学生作答、姓名、PII（脱敏这部分是有效的）。
- **时间窗**：2026-10-31 至 2026-11-05 17:19（本地），覆盖 K1.2/K1.3 的真实模型评测与 smoke 期间。
- **不可撤回**：内容已离开本机，本地侧无法删除第三方已接收的数据。

## 3. 修复内容

| 文件 | 改动 |
|---|---|
| `apps/api/src/config/env.ts` | 默认值 `true → false`；注释改回铁律口径，并写明「任何开启必须由数据主体显式逐次确认，禁止以默认开启+脱敏替代授权」 |
| `apps/api/.env.example` | `WEB_SEARCH_ENABLED=false` + 同样的授权说明 |
| `.env.example`（根） | 新增「数据主权 / 对外联网」段，显式 `false`，防止从根示例复制时漏配 |
| `apps/api/src/services/websearch/webSearchService.test.ts` | 新增 **P0-A/B/C** 3 条防回归测试；并给 2 条既有测试临时关 `WEB_SEARCH_AUDIT`，避免单测污染本地审计证据链 |

**P0-A**：读 `env.ts` 源码文本，断言默认值必须是 `false`（防止有人「顺手改回 true」）。
**P0-B**：关闭态下 mock `fetch` 计数，断言 `retrieveWebSearch` **零对外请求**、返回 `empty`。
**P0-C**：显式开启态下断言外发 URL 不含学生作答明文/编码。

> 未改动 `webSearchService.ts` / `sanitize.ts` 的业务逻辑与文件头注释——它们本来就符合铁律，
> 矛盾只在配置默认值。未删除或改写审计日志（证据链，须保留）。

## 5. 附带收益：p50 检索段

关闭默认联网检索后，归因链路不再等待对外网络（原 `WEB_SEARCH_TIMEOUT_MS=6s`，
且多引擎 fallback 会串行消耗该预算）。但这相对真实 27B 的 ~76s decode 只是零头，
**不能解决 G1 的 M4 p50≤30s BLOCKER**；完整耗时构成实测见
`docs/k1.5-G1闸门报告框架.md` §4.1。

## 6. 仍需数据主体决策 / 剩余风险

1. **历史 79 条已外发内容不可撤回**。是否需要在对外渠道做进一步说明、或按《个人信息保护法》
   行使撤回同意 / 请求删除 / 限制处理等权利，由数据主体决定；本记录不代做判断、不代发任何对外动作。
2. **审计日志留存**：`apps/api/src/data/websearch_audit.log`（本地）作为证据链保留，
   本轮未删除、未改写。是否归档或清理由数据主体决定。
3. **若将来确需联网检索**：必须逐次、显式确认，并写明用途 / 接收方 / 保留期；
   不得再次改回默认值 `true`（P0-A 测试会拦截）。
4. **K1.3 的 29 题 auto-eval 属历史数据**，结论不受本次默认值变更影响；
   未来重跑若需 web grounding，同样需显式授权。
5. 本轮只核查了 `services/` 下的对外路径；`ocr/recognitionAutostart.ts` 的 fetch 指向
   本机 OCR 服务（`localhost`），不属对外外发。
