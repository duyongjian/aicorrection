### 1.2 `DISABLE_THINKING` 陷阱（源码级证据）

- `apps/api/src/config/env.ts:73`：`DISABLE_THINKING: toBool(process.env.DISABLE_THINKING, true)` —— **默认 true**。
- `toBool`（同文件 23–26 行）只把 `'true'`/`'1'` 判为真，其余（含 `'false'`）一律 false；`dotenv` 不覆盖已存在的 `process.env` → 命令行前缀 `DISABLE_THINKING=false` 可生效。
- `apps/api/.env` 与 `.env.example` 均写 `DISABLE_THINKING=true`。
- 若未显式传：`apps/api/src/services/llm/ollamaProvider.ts:43-46` 会带 `chat_template_kwargs: { enable_thinking: false }`，**测的就不是用户指定的深度思考档**。
- 本轮所有评测命令统一前缀：
  `NO_PROXY='*' DISABLE_THINKING=false ANALYSIS_BASE_URL=http://127.0.0.1:8093/v1 ANALYSIS_MODEL=Qwen3.8-9B-Distill LLM_BASE_URL=http://127.0.0.1:8093/v1 LLM_MODEL=Qwen3.8-9B-Distill LLM_PROVIDER=ollama`

## 6. 遗留风险与下一步建议

1. **【最高优先】反号题极值配对不稳定**：11 次反号样本仅 5/11 正确、4/11 明确套模板。建议对 `nx05` / `my01` 各做 ≥30 次独立采样，给出 Wilson 区间；在此之前不得宣称根因解除。
2. **陷阱题回归**：`ry01` 思考档把「学生误判」当成真错因。怀疑长思考稀释了 `v0.2b` 的「防强行找错」指令，建议单独 A/B 验证（不接生产）。
3. **区间开闭约定**：模型习惯在驻点写半开区间，题面明确要求与定义域一致 → `nx02`/`nx05` 多次 `interval` FAIL。属真实指令遵循缺口，需产品决策是「改输出约束」还是「改题集判据」（**不得**为过门禁擅自放宽判据）。
4. **评分器假阴性**：`rc03`/`rc04`（关键词重叠）、`nx04`（`2^n - 1` 空格）建议加 `needs_human_review` 标记，避免把判据缺陷误读成模型退化；门禁口径保持不变。
5. **长尾与截断风险**：`nx02` 单次 1343 思考 token（占 1792 的 75%）、36.178s；`est_tokens` 无法预警。生产需监控 `finish_reason=length` 与 `predicted_n` 分布。
6. **格式**：`tm04` 缺「正确推导：」→ 三项齐全率 97.8% ≠ 100%。
7. **生产链路未验证**：3001 + RAG/检索 + 上传、n≥250 真实流量、认可率与盲评，全部仍为空缺。
8. **档位运维风险**：`DISABLE_THINKING` 默认 true，任何后续评测/生产调用只要漏传 `false`，就会静默退回「关思考档」并复现模板错误（§1.4 已实证）。建议把该开关的档位语义写入部署清单（本轮**未改代码**）。
