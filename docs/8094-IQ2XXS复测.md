## 1. 口径修正：服务层 reasoning 本来就是关的（重要）

上一轮规格卡《`reports/8094-eval/TARGET-SPEC.md`》把 IQ1_M 的 1792 token 自我纠缠归因为「思考档未关」，**该归因错误**，主理人指出后已用一手证据复核：

### 1.1 两层开关不是一回事【实测】

| 层 | 参数 | 8094 实际值【实测】 | 作用 |
|---|---|---|---|
| llama.cpp 输出解析 | `default_generation_settings.params.reasoning_format` | **`"none"`** ✅ 已关 | 是否把 `<think>` 内容分离到 `reasoning_content` |
| 同上 | `reasoning_in_content` | `false` | 思考文本是否混进 `content` |
| chat_template 渲染 | `chat_template_kwargs.enable_thinking` | **请求体显式传才生效** | 是否往 prompt 插思考引导 |

- `/props` 实测含 `<think>` 的 chat_template 与 `chat_template_caps.supports_preserve_reasoning=true`，但**这只代表模板能力，不代表服务默认开思考**。
- 请求体核查：8093 原始请求、IQ1_M 的「开档」请求均**无 `chat_template_kwargs` 字段**；只有显式构造的 off 版才带 `enable_thinking:false`。

### 1.2 同权重同题三档 A/B【实测，n=1/档，定性线索】

| IQ2_XXS / `mx01` | 裸请求（不传 kwargs，**服务默认**） | 显式 `false` | 显式 `true` |
|---|---|---|---|
| wall | **10.37s** | 10.94s | **73.99s** |
| `finish_reason` | `stop` | `stop` | **`length`（吃满 1792）** |
| `content` / `reasoning_content` | 391 / 0 | 384 / 0 | **0 / 3812** |
| completion_tokens | 248 | 233 | 1792 |
| decode R | 25.12 tok/s | 25.08 tok/s | 24.69 tok/s |
| 数学结论 | **±1 正确** | ±1 正确 | 无输出 |

**因果修正**：
1. 裸请求即干净 → 服务默认走**非思考分支**，`reasoning_format=none` 生效，主理人的配置是对的。
2. IQ1_M 裸请求下的 1792 token 绕圈 / `±√3` 错误，是**极低量化本身的退化**，不是思考档；IQ2_XXS 用完全相同的裸请求就正常。
3. 真正踩坑的是**显式传 `enable_thinking:true`**：思考链虽成功分离到 `reasoning_content`，却吃满上限截断、`content` 全空、74s → 完全不可用。
4. 因此规格应精确改写为：**请求层不要传 `enable_thinking:true`；服务启动参数无需改动**。`run-eval.sh` 的 `DISABLE_THINKING=true` 接线正确，保留。

## 7. 判定与下一步建议

**判定：NO-GO（离线门禁）**，但相对第 1 轮是**明确进步**，不需要再换量化档来「救基础能力」。

优先级建议：

1. **先攻「答案行套模板」根因**（本轮唯一主要质量瓶颈，且 8092/8093/本轮三代都卡在这里）
   - 这是 **prompt / 解码约束层**问题，不是量化问题：反号题 0/2、答案行与推导脱钩，说明模型能推对但写答案时回退到记忆模板。
   - 可试：在 `v0.2b-guard-trap` 之上加「答案行必须由推导末行逐字搬运」的显式约束，或把 `correct_answer` 改为从推导中抽取而非自由生成；用 12 题单调专项做 A/B，判据是**反号 2/2 + 严格数值 FAIL=0**。
2. **服务参数只需两处小改**（非阻塞）：`n_ctx` 8192 → 16384+；`temperature` 0.5 → 0.2、评测固定 seed。
3. **思考档保持现状**：服务 `reasoning_format=none` 正确；**请求层禁用 `enable_thinking:true`**（显式开档会 74s 截断且 content 空）。
4. **decode R 25.1 tok/s** 不达标但非当前阻塞（端到端已 ≤15s）。若后续要提速，考虑换 9B/14B 高精度档或 GPU offload 层数，而不是继续降精度。
5. **G1 仍未启动**：以上全是离线 harness 结果，不能替代真实用户认可率与人工盲评（Q8）。

## 8. 局限与诚实边界

- 本报告**全部为离线 `prompt:ab` 直连 provider 口径**：不含 3001 API、上传/OCR、RAG 锚点注入、联网检索、多轮追问；生产端到端延迟必然更高。
- P0 A/B 为 **n=1/档单次抽样**，只作定性因果线索；统计结论以 §3（12 题）、§4（34 题）为准。
- 重复采样一致性仅 **n=2**，不满足规格卡 Q4 的 ≥8 次口径，只记为线索。
- 跨档对比存在**口径差异**：IQ1_M/IQ2_XXS 为关思考档，8093 为深度思考档；延迟与 token 量不可严格横比，表中已标注分项口径。
- `auto-eval` 的「契约齐全 / 因果机制 / 结构信号等级」是**结构代理量，不是质量分**；人工盲评字段全部为「待评」，机器不给分。
- **数据主权**：全部请求与产物均在本机 `127.0.0.1` 与本地 `reports/` 内闭环，未外发、未参与任何训练或第三方共振。
