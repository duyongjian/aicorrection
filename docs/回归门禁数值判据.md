## 1. 缺陷根因

### 1.1 现象

Qwen3.5-4B 在 29 题真题回归门禁上用 `v0.2b-guard-trap` 变体得到 **27 PASS / 2 PARTIAL / 0 FAIL、陷阱未瞎编 1/1，门禁通过**；
但在标杆题 `f(x)=x^3-3x` 于 `[-2,2]` 的单调区间与极值上 **0/10 正确**，端到端 `correct_answer` **0/3 正确**。门禁形同虚设。

### 1.2 根因

`auto-eval.mjs` 的 `evalTeach()` 综合判定是「三选一即通过」：

```js
if (numsMatchFlag || specialMatch || (keywordMatch && overlap >= 0.1)) return PASS;
```

三个分支都无法检出错在「配对关系」的答案：

| 分支 | 逻辑 | 为什么漏 |
|---|---|---|
| `numsMatchFlag` | 只把答案行**第一个数字**与 truth **最后一个数字**比较（5% 容差）；不等时退回「任意数值有交集即通过」 | 极值题 truth 含 `-2, 2, -1, 1, 3`，模型把 `f(-1)=2` / `f(1)=-2` 写成 `f(1)=2` / `f(-1)=-2`，**数字集合完全一致**，照样撞上交集 |
| `specialMatch` | 双方都含「正确/错误/收敛」等词即通过 | 与数值无关 |
| `keywordMatch` | truth 任一中文词出现在答案里即通过 | 「极大值/极小值/驻点」这些词两边都有 |

即：**格式（五段）齐全 + 数字集合有交集 ⇒ PASS**，而符号、正负、配对结论从不校验。

### 1.3 题集缺口

`real-exam-v1` 的 29 题里只有 4 道 `mode=teach`（`tm01` 积分=2、`tm02` 自由落体 20m、`tm03` 1 mol、`tm04` 虚拟语气），
全是单步基础计算或文字题，检不出多步符号推导错误。

### 1.4 修复思路

1. 追加 4 道多步数值计算专项 `teach` 题，带**结构化金标准 `expected_facts`**，把「驻点 ↔ 极值类型 ↔ 函数值」等断言显式声明出来；
2. `auto-eval.mjs` 对带 `expected_facts` 的 case 走**严格数值一致性判据**：必须校验**配对绑定**（`f(at)=value`、坐标 `(at,value)`），禁止只做数字集合交集；
3. 其余 case **评分逻辑一行不改**，历史报告重跑结论完全相同。

## 2. `expected_facts` 字段 schema（`schema: 1`）

挂在单个 case 上，与 `provisional_truth` 并列：

```json
"expected_facts": {
  "schema": 1,
  "tolerance": 0.05,
  "assertions": [ /* 断言数组，见下 */ ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema` | number | 固定 `1`，便于后续演进 |
| `tolerance` | number | 数值相对容差，缺省 `0.05`；期望值为 0 时用绝对容差 `0.01` |
| `assertions` | array | 断言列表，**必须全部满足**才判 PASS；空数组直接 FAIL（`numeric_facts_empty`） |

### 2.1 断言公共字段

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `kind` | string | 必填 | `pair` / `set` / `interval` / `text`；v3 增加 `monotonic_direction`（见 §2.7） |
| `label` | string | 必填 | 人类可读断言名，也用于定位「标签子句」与写进 FAIL `detail` |
| `source` | string | `any` | `answer` = 只消费 `fields.correct_answer`（无则回落 `r.text` 的「正确答案：」行 / 全文）；`derivation` = 只消费 `fields.derivation`；`any` = 三者合并 |
| `match_any` | string[] | `[label]` | 用于定位子句的锚点子串（任一命中即取该处子句）。**缺省时用 `label`** |

> **消费优先级**：`results[].fields.correct_answer` + `fields.derivation` → 回落 `r.text`。
> `text` 断言使用未归一化的原文（保留 `2^{n}` 等写法），其余断言使用归一化文本。
>
> **子句（clause）**：从锚点向左回退到最近句读、向右推进到最近句读（逗号仅在括号外才算结束），
> 上限左 60 / 右 140 字符。目的是把断言限定在标签所在那一小段，避免跨标签串味。

### 2.2 `pair` —— 配对断言（核心）

```json
{ "kind": "pair", "label": "极大值", "at": -1, "value": 2, "source": "answer" }
```

| 字段 | 说明 |
|---|---|
| `at` | 位置 / 自变量 / 下标（如 `x=-1`） |
| `value` | 该位置对应的取值（如 `f(-1)=2`） |

判据：在 `label` 子句内必须检到一条 **(at, value) 同时正确** 的配对绑定（**存在性判定**：只要有一条正确即满足，不排除同一答案里并存的错误 / 自相矛盾绑定，见 §6 #11）。支持的绑定形式：

- 函数 / 数列式：`f(-1)=2`、`a_3=7`、`a(5)=31`、`S(2)=3`
- 坐标式：`(1,-2)`、`(-1, 2)`（拐点 / 极值点坐标）
- 保守回落（子句内无任何绑定时）：要求 `x=<at>` 与 `<value>` 同时出现在同一子句

**只罗列数字不构成绑定**。因此把 `f(-1)=2 / f(1)=-2` 写反成 `f(1)=2 / f(-1)=-2` 时，
检到的是 `(1,2)` 与 `(-1,-2)`，期望的 `(-1,2)`、`(1,-2)` 均不存在 → FAIL。

### 2.3 `set` —— 集合断言（全部出现，不是交集）

```json
{ "kind": "set", "label": "驻点", "values": [-1, 1], "match_any": ["驻点", "f'(x)=0", "解得"], "source": "any" }
```

| 字段 | 说明 |
|---|---|
| `values` | 子句内**每一个**都须出现（容差内），缺一即 FAIL |
| `exclude` | 可选；子句内出现其中任一数值即 FAIL |

`±1` 会自动展开为 `-1` 与 `1`；指数 `^2`/`^{3}` 会被剔除，不污染数值抽取。

### 2.4 `interval` —— 区间开闭断言

```json
{
  "kind": "interval", "label": "增区间",
  "segments": [
    { "left": -2, "right": -1, "left_bracket": "[", "right_bracket": "]" },
    { "left":  1, "right":  2, "left_bracket": "[", "right_bracket": "]" }
  ],
  "source": "answer"
}
```

逐段校验端点数值 **和** 开闭括号；`left_bracket` / `right_bracket` 可写字符串或允许值数组。
`parseIntervals` 识别 `[a,b]` / `(a,b)` / `±\infty` 端点。

### 2.5 `text` —— 子串断言

```json
{
  "kind": "text", "label": "导数符号",
  "all_of": [["f'(x)>0", "f′(x)>0"], ["f'(x)<0", "f′(x)<0"]],
  "source": "any"
}
```

| 字段 | 说明 |
|---|---|
| `all_of` | 每一项须命中；字符串 = 必须包含，数组 = 任一命中即可 |
| `any_of` | 至少命中一个 |
| `none_of` | 任一命中即 FAIL |

用于「导数符号」「二阶导符号翻转」「通项写法」这类结构性描述；**是子串检查，不是语义证明**。

### 2.6 新增 4 道专项题

| id | 覆盖 | 关键断言 |
|---|---|---|
| `nx01` | ① 极值三元配对（`f(x)=x^3-3x` 于 `[-2,2]`） | `set 驻点 [-1,1]`、`pair 极大值 (-1,2)`、`pair 极小值 (1,-2)` |
| `nx02` | ② 单调区间开闭与导数符号 | `interval 增/减区间`（闭括号）、`text` 导数正负、`pair` 两极值 |
| `nx03` | ③ 二阶导 / 拐点与正负号翻转 | `pair 拐点 (1,-2)`、`set 二阶导零点 [1]`、`text` 符号翻转 |
| `nx04` | ④ 数列 / 方程多步求解 | `pair a_3 (3,7)`、`pair a_5 (5,31)`、`set 方程两根 [2,3]`、`text 通项` |

真值：`f'(x)=3(x-1)(x+1)`，驻点 `±1`，`f(-1)=2`（极大）、`f(1)=-2`（极小）；
`f''(x)=6x-6`，拐点 `(1,-2)`；`a_n=2^n-1`，`a_3=7`，`a_5=31`，`x^2-5x+6` 两根 `2,3`。

### 2.7 `monotonic_direction` —— 方向标签与区间集合双向绑定（v3 新增）

```json
{
  "kind": "monotonic_direction",
  "label": "单调方向绑定",
  "source": "answer",
  "strict_brackets": false,
  "increasing": {
    "match_any": ["单调递增区间", "增区间", "递增区间"],
    "segments": [{ "left": -2, "right": -1 }, { "left": 1, "right": 2 }]
  },
  "decreasing": {
    "match_any": ["单调递减区间", "减区间", "递减区间"],
    "segments": [{ "left": -1, "right": 1 }]
  }
}
```

判据（三条全部满足才 PASS）：

1. 每个方向用 `match_any` 锚点（缺省用内置别名表）定位**该方向自己的子句**，子句内必须出现该方向 `segments` 的全部区间（端点数值容差匹配）；
2. **方向互斥**：每个方向的子句内不得出现另一方向的期望段 —— 这是「增/减整体写反」的直接信号，也是旧 `interval` 断言缺的能力（§6 #5：只要求期望段出现，不禁止额外区间）；
3. 两个方向都必须给出区间；任一方向的标签未命中、子句内无区间表达式，或期望段未声明，均 FAIL。

| 字段 | 说明 |
|---|---|
| `increasing` / `decreasing` | 各自的 `{ match_any?, segments[] }`；`segments[]` 元素为 `{left, right, left_bracket?, right_bracket?}` |
| `strict_brackets` | 默认 `false`：只校验端点数值，容忍教材 `[-2,-1]` / `[-2,-1)` 开闭差异；`true` 时逐段校验括号。严格开闭仍由同 case 的 `interval` 断言负责 |
| `match_any` | 方向标签别名。内置表覆盖「单调递增区间 / 单调增区间 / 递增区间 / 增区间 / 上升区间」及其递减对应，避免旧 `interval` 用字面 `增区间` 找不到锚点而误杀 |

别名可能在同一处多次命中（如「单调递增区间」同时含「递增区间」「增区间」），解析结果会按 `left/right/括号` 去重后再判定与展示。`reason` 为 `numeric_direction_mismatch`（优先级高于 pair / interval / set），`detail` 会列出每个方向实际检到的区间与「方向写反」的具体冲突段。

## 3. 判据规则

`evalNumericFacts(r, expectedFacts)`：

1. 无 `expected_facts` 的 case → **完全不走这里**（见第 4 节）。
2. 组装 `sources`：`fields.correct_answer` → `fields.derivation` → `r.text`。三者全空 → `FAIL / numeric_missing_answer`。
3. 逐条执行 `assertions`，**全部满足** → `PASS / numeric_facts_match`。
4. 任一不满足 → `FAIL`，`reason` 取最具体的一类，`detail` 逐条列出「期望什么 / 实际检到什么」：

| reason | 触发 |
|---|---|
| `numeric_pair_mismatch` | 任一 `pair` 断言失败（最常见，含极大/极小配对写反） |
| `numeric_set_mismatch` | `set` 断言失败（如驻点算成 0/2） |
| `numeric_interval_mismatch` | `interval` 断言失败（区间端点或开闭不符） |
| `numeric_fact_mismatch` | `text` 断言失败 |
| `numeric_facts_empty` | 声明了 `expected_facts` 但无断言 |
| `numeric_missing_answer` | 结果无可消费文本 |
| `numeric_direction_mismatch` | v3：`monotonic_direction` 断言失败（增/减方向写反、方向标签缺失、两方向同区间） |
| `numeric_pair_mismatch` 等也会出现在 `--verbose` 逐题详情与 `reports/auto-eval/eval-*.json` 的 `eval` 字段里 |

`detail` 示例：

```
[pair/极大值] 期望 标签「极大值」处须出现配对 f(-1)=2；实际 检到配对 [f(1)=2] | [pair/极小值] 期望 标签「极小值」处须出现配对 f(1)=-2；实际 检到配对 [f(-1)=-2]
```

### 3.1 防「漏 `--set` 静默假结论」

评分前计算 `computeTruthHitRate(results, truthMap)`：`case_id` 命中题集中**非空** `provisional_truth` 的比例。

- 低于 `MIN_TRUTH_HIT_RATE = 0.6`（或 results 为空）→ **stderr 报错 + `process.exit(2)`**，提示显式传 `--set`。
- 上一轮踩坑：漏 `--set` 时用默认 `prompt-ab-set.json`（case_id 为 `m01..y02`），与 real-exam 报告 `rm01..tm04` 零重叠，truth 全空，误报 2 PASS / 27 FAIL。现在直接报错。
- `scripts/attrib-regress.mjs` 始终显式传 `--set`，且题集与报告 case_id 一致（命中率 100%），**不受影响**。

### 3.2 Windows `spawn('npm')` ENOENT

`attrib-regress.mjs` 原用 `spawn('npm', ...)`：Windows 上 npm 实际是 `npm.cmd`，直接 `spawn('npm')` → `ENOENT`，
`spawn('npm.cmd')` 不加 shell → `EINVAL`。修复：

- 优先复用 npm 运行脚本时注入的 `npm_execpath`（`npm-cli.js` 绝对路径），用 `process.execPath` 直接执行，完全绕开扩展名差异；
- 直接 `tsx scripts/attrib-regress.mjs` 时按 `process.platform === 'win32'` 用 `npm.cmd` + `shell: true`，并对含空格参数加引号；
- `node` 子进程也改用 `process.execPath`。

`SET` 默认值仍指向含新题的 `apps/api/src/tests/fixtures/prompt-ab-set-realexam.json`（`real-exam-v2`，33 题）。
门禁口径 **`FAIL=0 && 陷阱未瞎编率=100%`** 不变，PARTIAL 仍计入通过。

`未瞎编率: 0/0 (n/a (无陷阱题))` —— **`未瞎编率: 0/0` 前缀保留**，`gateFromAutoEval` 的
`/未瞎编率:\s*(\d+)\/(\d+)/` 正则仍可解析；此时 `trapOk = (0 === 0) = true`，**陷阱闸门自动通过**。

### 4.1 门禁口径变更显式声明（29 题 → 33 题）

题集 `version` 由 `real-exam-v1`（29 题）升到 `real-exam-v2`（**33 题**）后，
`attrib-regress.mjs` 的 `SET` 默认值指向新题集，**不带 `JSON=` 的默认全量回归将跑 33 题**，
其中新增的 4 道 `nx01~nx04` 带严格数值判据。

因此：**未来重跑全量得到的 PASS / PARTIAL / FAIL 分布，可能与历史 29 题报告的结论不同**。
这是**门禁口径主动收紧**（新增 4 道模型未针对训练过的多步数值题，且判据远严于 `evalTeach` 三选一），
**不是模型能力回归**，请勿拿历史 29 题基线去直接判定新跑结果「退步」。

反过来，历史报告本身**不含 `nx*` id**，用 `--set` 指向 `real-exam-v2` 重跑时，29 道历史 case 因无
`expected_facts` 全部走原判定式，仍可**逐字复现**（28/1/0 陷阱 1/1、27/2/0 陷阱 1/1、23/3/3 陷阱 0/1）。
要做同口径比较，必须固定题集与报告：复现历史用 29 题 id 的报告，验收新判据用含 `nx*` 的新报告。

### 5.2 合成等价压力测试（题干为等价改写，≥9 条 FAIL）

> **定性说明（P1，务必照实理解）**：这一节**不是「历史报告回放」，也不是「同一道题的 10 次输出」**。
> 它是把现成报告里的 10 条模型输出**挂到 `nx01` 的结构化金标准上，做一次合成等价压力测试（题干为等价改写）**。
>
> - **原题**（见 `reports/prompt-ab-2026-11-05T16-24-06-4b-ext.md` 的 10 行「题干」）：
>   「设函数 $f(x)=x^3-3x$，求其在区间 $[-2,2]$ 上的单调区间与极值。」
> - **`nx01` 题干**：额外要求「驻点」，并强制「作答须显式写出『驻点 x=?、极大值 f(?)=?、极小值 f(?)=?』的配对关系，不能只罗列数字」。
> - 两者**数学内核相同**（同函数 `f(x)=x^3-3x`、同区间 `[-2,2]`、同极值 `f(-1)=2` / `f(1)=-2`），
>   但**指令集不同，并非逐字同一题**。因此下面的结论只能读作「这 10 条输出若按 `nx01` 的判据去评，会被拦下」，
>   **不能**读作「同一题重跑得到相同结论」，更不能当作历史可比性证据。
> - **报告本身不含题干**：顶层键为 `generated_at, set, set_version, provider, timeout_ms, variants, summary, case_diffs, results`，
>   `case_diffs=[]`、**无 `cases` 键**，`results[]` 无 question / 题干字段，`results[].text` 只有模型输出；
>   原题**只能从同名 `.md` 的「题干」行恢复**。
> - **为何仍然有效**：10 条 `fields.correct_answer` **全部自带 `f(?)=?` 绑定**（`f(1)=2`、`f(0)=0`、`f(2)=-4` 等），
>   `nx01` 的 `pair` 断言确实被触发并逐条比对配对关系，不是靠「缺字段 / 缺绑定」蒙混成 FAIL。
> - **覆盖不全（如实标注）**：这 10 条的单调区间几乎全错（`[-2,0]`、`[2,2]`、`[0,2]`、`(-∞,-1)` 等），
>   但 `nx01` 的 `expected_facts` **不校验单调区间**（该维度由 `nx02` 覆盖）。
>   10 条 FAIL 的 `reason` **全部为 `numeric_pair_mismatch`**（`pair` 失败优先于其他 reason）：实测其中
>   **9 条仅 `pair` 断言失败**，另 1 条（#3）还伴随 `set 驻点` 定位锚点未命中，但**无一条因单调区间被拦下**。
>   属**单题覆盖不全**：本节只证明配对判据有效，不证明这 10 条输出的所有错误都被检出。
> - 现成报告 10 条结果的 `case_id` 实际是 **`ext01..ext10`**，并非全部 `ext01`；故构造等价离线 report：
>   把 10 条 `case_id` 统一改写为 `nx01`，跑完即删。
>   新跑一次 `prompt:ab --set <real-exam-v2>` 时结果 id 天然是 `nx01..nx04`，无需改写。

```bash
node -e "

const src='reports/prompt-ab-2026-11-05T16-24-06-4b-ext.json';
const r=JSON.parse(fs.readFileSync(src,'utf8'));
r.results=r.results.map(x=>({...x, case_id:'nx01'}));
fs.writeFileSync('reports/_tmp-ext-replay.json', JSON.stringify(r));
"
node apps/api/src/tests/auto-eval.mjs \
  --json reports/_tmp-ext-replay.json \
  --set apps/api/src/tests/fixtures/prompt-ab-set-realexam.json --verbose
rm -f reports/_tmp-ext-replay.json
```

合成压力测试实测：`总: 10 | PASS: 0 | PARTIAL: 0 | FAIL: 10`，失败原因 `{"numeric_pair_mismatch":10}`，
即 10/10 判 FAIL（验收要求 ≥9）。

## 6. 已知盲区

1. **只对声明了 `expected_facts` 的题生效**。29 道历史题与任何未声明金标准的新题仍走宽松的 `evalTeach` / `evalDiagnose`，
   三选一即 PASS 的缺陷在这些题上依然存在。要扩覆盖必须逐题补 `expected_facts`。
2. **不覆盖自由文本里的推导正确性**。`text` 断言只是子串存在性检查；`pair` 只校验 `correct_answer` 中声明的配对，
   推导过程是否严谨、是否自相矛盾（除已有 `answer_derivation_similarity` 筛查信号外）不作判定。
3. **要求显式配对写法**。若模型把「值」和「位置」分列两处、不写成 `f(-1)=2` / `(1,-2)` / `x=-1 … 2` 这类绑定，
   即使数学上正确也可能判 FAIL。这是刻意收紧：本判据的目标就是逼出可校验的配对，代价是可能误杀表述非常规的正确答案。
4. **`source: answer` 优先，推导不救场**。`pair` 断言默认只看 `correct_answer`：
   `correct_answer` 写错而 `derivation` 里写对，仍判 FAIL（如 ext 报告 #4）。反之，最终答案正确但推导写错不会被本判据发现。
5. **区间开闭采用固定约定**：定义域端点 `-2`、`2` 与驻点处均取**闭区间**。教材中写成开区间 `(-2,-1)`、`(1,2)`
   的等价表述会被判 FAIL；如需兼容，可在 `expected_facts` 里把 `left_bracket` / `right_bracket` 改为允许值数组。
   `interval` 目前只要求「期望段都出现」，不禁止额外区间（如同时写出 `(-∞,-1)`）。
6. **`set` 只校验「全部期望值都出现」**，不自动禁止额外数值（除非显式声明 `exclude`）。
7. **5% 相对容差**对整数结论是合适的，但不适合需要严格离散匹配的场景；可按 case 调小 `tolerance`。
8. **`text` 断言是子串级**，例如 `"f'(x)>0"` 与 `"f'(x)<0"` 同时出现即算满足，并不证明符号与 `x` 范围的对应关系正确。
   该部分仍依赖 `pair` / `interval` 断言补强。
9. **报告与题集必须匹配**。命中率守卫能挡住「漏 `--set` / 传错题集」，但如果报告里混入了题集外的 case_id
   且占比 < 40%，仍会继续评分；这类混合报告应先用 `--cases` 或修正题集。**另有一个更隐蔽的同源形态，单列为 #12**。
10. **本判据不接生产归因链路**。`apps/api/src/services/attribution/*` 未改动，guard prompt 接进生产是另一项需单独授权的任务。
11. **`pair` 是存在性判定，不排除同一答案内并存的错误 / 自相矛盾绑定**。判据只要求「标签子句内**存在一条** `(at,value)` 正确绑定」，
    不检查是否同时存在写反的绑定。QA 实测：在 `correct_answer` 里同时写
    「极大值 `f(-1)=2`，极小值 `f(1)=-2`」与「极大值 `f(1)=2`，极小值 `f(-1)=-2`」，
    `evalNumericFacts` 仍返回 **PASS / `numeric_facts_match`**（3 条断言全部满足）。
    即「正确配对 + 写反配对并存」这种自相矛盾输出不会被拦下；如需覆盖，须在 `expected_facts` 中增加
    「禁止绑定」类断言（当前 schema 尚未提供），或另行做答案内部一致性校验。
12. **不带 `--set` 且默认集 id 占比高时，守卫会放过并静默关闭严格判据**（QA 实测，比 #9 更隐蔽）。
    守卫只看「case_id 在题集中命中非空 truth 的比例」是否 ≥ 0.6，**不校验命中的是不是本该用的题集**。
    QA 构造「4 道 `nx*` + 25 个默认集 `prompt-ab-set.json` 的 id（`m01..` 等）」共 29 条、**不带 `--set`**：
    命中率 `25/29 = 86%` ≥ 60% → **exit 0 放过**；此时 `truthMap` 来自默认集，4 道 `nx*` 查不到 `expected_facts`，
    **静默回落宽松 `evalTeach`**，输出里**完全不出现「严格数值判据」段**（实测无该段，汇总是 `总: 29 | PASS: 6 | PARTIAL: 4 | FAIL: 19`）。
    危害是「看起来跑了、其实严格判据根本没启用」，且不会报错。
    **规避**：始终显式传 `--set <题集>`（`attrib-regress.mjs` 已这么做）；如需更强保证，应把守卫升级为
    「命中率 + 题集 version / id 命名空间」双重校验，但那属于源码改动，本次未做。
13. **`monotonic_direction` 不做「答案行 ↔ 推导段」自动交叉校验（v3）**。9B 的症状是推导段
    `f'(x)>0 ⇒ 递增` 写对、答案行把增/减写反；本判据只校验答案行的方向绑定，能**拦下**错误，
    但不自动比对推导段的符号结论、不解释成因。若要做自动交叉校验，须解析推导段里
    「导数符号 ↔ 区间 → 增减」的自由文本，鲁棒性差、易误杀，本轮未做（仍靠人工看报告归因）。
14. **方向断言依赖显式区间表达式（v3）**。模型若只写 `x<-1 或 x>1` 这类不等式、不写
    `[-2,-1]` 括号，解析不到区间即 FAIL。与 #3 同源，属刻意收紧：目标是逼出可校验的结构化写法，
    代价是可能误杀表述非常规但数学正确的答案。
