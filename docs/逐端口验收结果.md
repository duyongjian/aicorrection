### 二、关键纠正：V4 FAIL 根因是生产 prompt 设计，不是模型能力缺口

首轮「补测2」用**先判断再转写**的干净 prompt + 自然语言「非题目」+ 明确"不要转写"，模型正常输出「非题目」。但**生产修复 prompt** 把"转写"前置、用模型不买账的机器 token `[[NOT_A_QUESTION]]`，模型读到可读文字即执行主指令转写、忽略次要拒识从句（甚至自加"(这是一张风景照，无题目)"元注仍照转）。故 V4 在生产 prompt 下 0% 生效——**属可修复的 prompt 设计缺陷，非模型根本不能拒识**。代码校验层 `isRejectedOcrText` 本身正确（兼容自然语言「非题目」与机器 token），只要模型吐出 token 即可拦下。

#### 5. 真正可达标的可选路径（待决策，含准确率/范围权衡）
- **A. 双 serve 并行**：文本 serve + 公式 serve 各一，rapid/paddle 真并行 → 本地 OCR 由「串行和」降为「max」(~11s)；仍受争用抖动影响。

- **C. 降单引擎时延**：onnxruntime 线程数调优（`OMP_NUM_THREADS` 限核避免与 8090 抢资源）、图像预缩放（当前 fixture 已仅 456–820px，空间小）、评估启用 mkldnn（paddle 3.3.x 有 onednn 回归需谨慎）。
- **D. 资源隔离**：OCR 与 8090 视觉服务分机/分核，消除争用抖动（治本但需基础设施）。
- **E. 门禁再基线**：将 V5 阈值按「共享笔记本 + 同机争用」现实校准（如 ≤20s），并改测「本地 OCR 仅」时延（已在 harness 新增 `local_ocr_only` 指标隔离责任域），使门禁反映代码回归而非基础设施。

## 九、V5 门禁收口（自适应公式跳过，P1-b 终局，2026-11-10 深夜）

> 关联：实现改动 `ocrService.ts`（`recognizeImageLocal` 串行-条件式 + 自适应公式跳过）、`env.ts`（三新增旋钮 `OCR_FORMULA_BUDGET_MS` / `OCR_FORMULA_TEXT_SLOW_MS` / `OCR_FORMULA_COOLDOWN_MS`）；复验 harness `reports/8090-retest/retest.ts v5`。

### 一、改动要点

- **串行-条件式本地 OCR**（前置已落）：先跑轻量 text serve（rapid），仅当文本提示需公式（`shouldTryFormula`）或为空（纯公式图）才跑重型 formula serve（paddle+PP-FormulaNet-S），二者错峰，消除双 serve 并行抢 CPU 的 ~22s 尖刺。
- **公式识别硬预算**（`FORMULA_BUDGET_MS` 默认 5000ms）：`withTimeout` 包裹 formula serve 调用，超预算即 `catch→null` 放弃 LaTeX、返回纯文本，墙钟稳定压在「文本 + 预算」内。常态 4s 内完成仍拼入 LaTeX（保 V2 字段级准确率）。
- **重负载自适应跳过**（本次关键兜底）：
  - `OCR_FORMULA_TEXT_SLOW_MS`（默认 6000ms）：文本识别已超阈值 → 机器 CPU 被外部负载（同机 8090 视觉模型等）占满，公式几乎必超预算，直接跳过公式路、牺牲 LaTeX 保时延。
  - `OCR_FORMULA_COOLDOWN_MS`（默认 20000ms）：一次公式超预算即说明 paddle serve 慢推理在后台仍吃 CPU ~13–16s，设冷却窗口跳过后续公式路，让其跑完释放 CPU，避免污染下一请求的文本识别（这正是 §8 权威复测 16.9/17.1s 的真凶：超时公式 serve 后台 churn 拖慢热样本）。
