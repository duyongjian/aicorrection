## 1. 结论速览（回答"是不是现在答不对"）

**是，但要说准**：不是"全答不对"，也不是"数学算不出来"，而是

> **9B 的「正确推导」段基本算对了，但「正确答案」行不看题干函数，直接吐一套固定模板**，
> 导致增/减区间或极值配对与推导自相矛盾。速度、格式、合规率都达标，唯独**结论不可信**。

| 维度 | 现状 | 判定 |
|---|---|---|
| 延迟 | p50 ≈ 7.6s、decode ≈ 41.82 tok/s | ✅ 达标（≤30s） |
| 格式合规 | A/B 36/36 `status=ok`、LaTeX 100% | ✅ 达标 |
| 数学结论 | 原题 10 次采样 `v0.2b-guard-trap` **0/10** 方向正确；`v0.1` **4/10** | ❌ 不达标 |
| 泛化 | 反号对照题 2/2 方向"碰巧对"，但极值配对 2/2 写反 | ❌ 不稳定 |
| G1 闸门 | 认可率、盲评准确率、n≥250 真实样本 | ❌ **OPEN BLOCKER** |

**本轮没让模型变对**，做的是三件实事：把"写反"变成能自动拦下的判据、把正确率量化清楚、把"调 prompt 能不能修"实测到底。

## 2. 根因：答案行模板固化（不是算错）

同一套模板在**两道增减方向恰好相反**的题上表现如下（真实输出，摘自 `reports/prompt-ab-2026-11-06T03-14-43-9b-mono-ab.json`）：

| 题 | 正确结论 | 9B 答案行（`v0.2b-guard-trap`） | 结果 |
|---|---|---|---|
| `mx01` $f(x)=x^3-3x$ | 增 $[-2,-1]\cup[1,2]$、减 $[-1,1]$；极大 $f(-1)=2$、极小 $f(1)=-2$ | 增 $[-1,1]$；减 $[-2,-1]\cup[1,2]$；极大 $f(-1)=2$、极小 $f(1)=-2$ | 区间反、极值对 |
| `my01` $g(x)=-x^3+3x$ | 增 $[-1,1]$、减 $[-2,-1]\cup[1,2]$；极大 $g(1)=2$、极小 $g(-1)=-2$ | 增 $[-1,1]$；减 $[-2,-1]$ 和 $[1,2]$；极大 $g(-1)=2$、极小 $g(1)=-2$ | 区间对、极值反 |

即模型不论题干是 $f$ 还是 $g$，答案行几乎固定为
`增 [-1,1]、减 [-2,-1]∪[1,2]、极大 (?) (-1)=2、极小 (?) (1)=-2`。
而同一段「正确推导」里写的 $f'(x)>0 \Rightarrow$ 递增 是对的 —— **答案行与推导脱钩**。

这解释了此前三个看似矛盾的现象：

1. ext 10 次采样 `guard` **0/10**（区间写反），`v0.1` **4/10**；
2. 33 题门禁的 `nx02`（题干明确要求"由 $f'(x)$ 符号写出区间"）`guard` 却答对 → **题干措辞能唤醒计算，但不稳定**；
3. 反号题方向判据 2/2 通过、极值配对 2/2 失败 → 不是"系统性方向反转"，是**套模板碰巧撞对一半**。

## 3. 判据升级：`monotonic_direction`

旧判据为什么拦不住：`evalTeach` 三选一即 PASS；`interval` 只要求"期望段是否出现"且标签字面必须是「增区间/减区间」（写「单调递增区间」会找不到锚点而误杀）；`text` 只是子串存在性，不绑定方向。

`apps/api/src/tests/auto-eval.mjs` 新增断言类型（字段 schema 见 `docs/回归门禁数值判据.md` §2.7）：

```json
{
  "kind": "monotonic_direction",
  "source": "answer",
  "strict_brackets": false,
  "increasing": { "segments": [{"left":-2,"right":-1},{"left":1,"right":2}] },
  "decreasing": { "segments": [{"left":-1,"right":1}] }
}
```

三条硬规则：**① 每个方向的期望段必须全部出现在该方向子句内；② 每个方向子句内不得出现另一方向的期望段（写反的直接信号）；③ 两个方向都必须给出区间**。
标签别名内置（单调递增区间 / 单调增区间 / 递增区间 / 增区间 / 上升区间 及递减对应），解析结果按端点+括号去重；`strict_brackets=false` 时只比端点数值，容忍教材 `[-2,-1]` / `[-2,-1)` 开闭差异。
失败 `reason` = `numeric_direction_mismatch`，优先级高于 pair / interval / set。

**硬约束**：`evalTeach` / `evalDiagnose` 判定式一行未改；未声明 `expected_facts` 的题仍走原判定式。

## 6. Prompt A/B：能不能靠加约束修掉？

在 `promptVariants.ts` 注册两个**离线评测专用**候选（不接生产，`DEFAULT_VARIANT_ID` 仍为 `v0.2b-guard-trap`），只改 `teach` system，规则内不含任何具体结论：

- `v0.2c-monotonic-check`：在 system **末尾**追加「答案行须与推导的导数符号结论逐项回读核对」；
- `v0.2d-monotonic-prefix`：同一规则放到 system **最前**（排除"指令靠后被忽略"）。

命令（本地 8092，`NO_PROXY='*'`，12 题 × 3 变体 = 36 次）：

```bash
ANALYSIS_BASE_URL='http://127.0.0.1:8092/v1' ANALYSIS_MODEL='Qwen3.5-9B' \
LLM_BASE_URL='http://127.0.0.1:8092/v1' LLM_MODEL='Qwen3.5-9B' \
npm run prompt:ab -- --set apps/api/src/tests/fixtures/prompt-ab-set-monotonic.json \
  --provider real --variants v0.2b-guard-trap,v0.2c-monotonic-check,v0.2d-monotonic-prefix \
  --tag 9b-mono-ab
```

结果（`reports/prompt-ab-2026-11-06T03-14-43-9b-mono-ab.json` + `reports/auto-eval/eval-2026-11-06T03-14-57.md`）：

| 变体 | 合规率 | 原题方向 10 题 | 反号题方向 2 题 | 全断言 PASS | 平均延迟 |
|---|---|---|---|---|---|
| `v0.2b-guard-trap`（对照） | 12/12 | **0/10** | 2/2 | **0/12** | 7.2s |
| `v0.2c-monotonic-check`（末尾） | 12/12 | **6/10** | 2/2 | **6/12** | 6.9s |
| `v0.2d-monotonic-prefix`（前置） | 12/12 | **0/10** | 2/2 | **0/12** | 8.1s |

判读：

1. **末尾追加的语义一致性回读确实有效**：原题方向正确率 0/10 → **6/10**，且延迟没有变差；说明"让模型回读自己的推导"能唤醒计算。
2. **同一规则前置完全无效（0/10）**，指令位置高度敏感 → 这个修复很脆，不能当作稳定方案。
3. **反号题全变体 0/2 全断言通过**：方向碰巧对，但极值配对仍套模板（`g(-1)=2` 极大 / `g(1)=-2` 极小，正确应相反）。**换一道函数就不会算**，泛化未解决。
4. 6/10 = 60%，远低于 G1 的认可率 ≥70% / 盲评准确率 ≥80%，且这只是**单道题的 10 次重复采样**，不构成 G1 证据。

**结论：prompt 单改能把症状压下去一半，但不足以达标，且不可迁移到新题。不能再靠继续堆 prompt 提示。**

## 7. 下一步决策（按对症程度排序，均未执行、需授权）
